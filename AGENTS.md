# LiftCode Server

This repository is the production backend for the LiftCode app and a hands-on project for learning backend development. The user leads feature design and implementation. The agent reviews the user's work and explains its findings.

## Feature Reviews

1. When the user describes the feature they are implementing, first inspect the relevant screens, data flow, and API calls in the sibling app repository at `../LiftCode`.
2. Review the user's server code against the stated requirements and the client behavior. Point to the relevant code, explain what works and what needs improvement, and describe the effect on the feature.
3. Suggest improvements when the current approach fits the requirements. If the underlying design is unsuitable, recommend a different approach and explain what it would solve.

By default, provide review findings and their reasoning. Edit code when the user explicitly asks. Keep explanations focused on what the user needs to understand and revise the implementation.

## Documentation and Git

- Write all repository documentation and commit messages in English.
- Name branches using a change-type prefix and a lowercase, hyphen-separated description. Use prefixes such as `feat/` for features, `style/` for formatting, and `chore/` for maintenance. For example, use `feat/database-connection` for database connection work.
